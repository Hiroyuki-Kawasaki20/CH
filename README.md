# CHかんばんセット

CH（車体）ラインのかんばん自動仕分け・工程割当ツール。  
現行GUIは CustomTkinter ベースで、引取作業者1人の運用に合わせてメイン工程・リリーフ工程・あふれを扱います。
工程割当は新スケジューラ（EDF + 同便クラスター連続 + アイドル部分充填）を優先し、
同等以上でない場合は既存ロジックへフォールバックします。

主な運用機能:
- セットボード3レーン表示（メイン/リリーフ/あふれ）
- 直選択（1直/2直）
- 同一直での工程別引継ぎ時刻（連続実行時）
- 自動再読込（毎時の指定分実行）
- バッテリー交換オプション（仮想山-1を挿入）
- SPO用Excelの安全出力（排他・一時書込・同期待機）

補足:
- **SPO出力ファイルの出力先分離**: Power Automateの多重トリガー防止のため、以下のように出力先を分離しています：
  
  | ファイル | 出力先 | 備考 |
  |---|---|---|
  | `SPOアップロード用.xlsx` | SPO監視フォルダ（OneDrive共有） | Power Automate監視対象 |
  | `SPOアップロード用_履歴.xlsx` | Windows利用者別のローカル出力先 | トリガー対象外 |
  | `SPOアップロード用_未ヒット一覧.csv` | Windows利用者別のローカル出力先 | 入車時間マスタ照合外の便（調査用ログ） |

- SPO出力のテーブル付与（`SPOExport`）は `src/services/spo_export.py` 側で一元実施する運用です。
- `src/utils/excel_utils.py` の `_add_table_exact` は同名テーブル再呼び出し時にスキップする冪等実装です。

保存先・初回のフォルダ選択・別Windowsユーザーでの運用は[起動・exe化ガイド](docs/起動・exe化ガイド.md#4-windows利用者ごとの初回設定保存先)を参照してください。旧設定・共有履歴の自動移行は行いません。前回工程終了時刻もWindows利用者別です。

## 入車時間マスタの管理（SharePoint同期フォルダ）

`入車時間マスタ.xlsx` は、通常運用では初回に選択した入力フォルダ（利用者別設定の`base_dir`）直下へ配置します。出荷情報CSVや出荷場一覧CSVと同じフォルダに置くことで、読み込みと保存が同じファイルを参照します。

| 優先順位 | 参照先 | 用途 |
|---:|---|---|
| 1 | `master_path` | 個別指定用。ファイルパスまたはフォルダパスを指定できます。通常は未設定です。 |
| 2 | `base_dir/入車時間マスタ.xlsx` | 通常運用の配置先。SharePoint(OneDrive) 同期フォルダ直下です。 |

設定された上記候補の中では、従来どおり既存ファイルを優先します（両方あれば`master_path`優先）。どちらにも無ければ親フォルダが存在する最優先候補を新規作成先にし、全親が無い場合も設定の先頭候補を維持して保存時にエラー・救済退避とします。**repo直下・exe隣のマスタへ暗黙にフォールバックしません。** 未設定なら入力フォルダの選択を案内します。明示的な読込・保存パス引数と救済保存は従来どおりです。

SharePointブラウザで編集する場合は、対象ライブラリで `入車時間マスタ.xlsx` を開き、編集後に保存状態とOneDrive同期完了を確認してからツールを操作してください。ツールで保存する前にExcelやブラウザ編集画面で同じファイルを開いていると、保存は中断され、編集内容は `%TEMP%` 配下の `入車時間マスタ_未保存_日時.xlsx` に退避されます。

注意事項:
- 保存先フォルダが見つからない場合、ツールはフォルダを自動作成しません。SharePoint同期フォルダの設定と同期状態を確認してください。
- `入車時間マスタ.xlsx` が見つからない場合でも、ツールは空のマスタとして起動します。保存時は決定済みの同じパスへ書き込みます。
- 同じフォルダに `入車時間マスタ*` の類似ファイルがある場合、OneDrive同期競合の可能性があります。正しいファイルを `入車時間マスタ.xlsx` に戻してから利用してください。

### GUI保存後のExcel直接編集・Power Apps接続

- GUI保存時は `NONYUHIBIN`（便番号）と `入車時間` の値を文字列として保存し、セルの表示形式も「文字列（`@`）」に設定します。`01`、`08:30`、`25:10` などの文字列を保持し、欠損は空欄にします。既に数値化された `1` を `01` に戻す機能ではありません。
- 最終データ行の次の **100行** も、対象2列に文字列書式だけを設定します。値やダミー行は追加せず、マスタ再読込時のデータ件数も増えません。100行を超えて入力する場合は、Excel側で文字列書式をコピーするなどの対応が必要です。
- 通常の貼り付けは貼り付け元の書式を持ち込むため、**値の貼り付け**を推奨します。
- シート「入車時間マスタ」に、固定名 **`PickupTimeMaster`** のフィルタ付きExcelテーブルを毎回作成します。列順は `OData_納入先` / `NONYUHIBIN` / `入車時間` / `セットありフラグ` のままです。テーブル名はPower Appsの接続先として使用するため、不用意に変更しないでください。
- テーブル範囲は見出し＋実データ行だけです（例：78件なら `A1:D79`）。入力用100行は含めません。Excelで直接行を追加した際は、テーブル範囲が新しい行まで拡張されているか確認してください。
- 保存関数は0件でも見出しだけのテーブル（`A1:D1`）を作成できますが、GUIの「データなしでは保存しない」動作は従来どおりです。空テーブルをPower Appsで利用できるかは未確認です。
- Power Apps側では、ファイルとテーブルへの接続設定が別途必要です。GUI保存時は従来どおりxlsxを再生成するため、既存接続が保存後も維持されるかは実環境で確認してください。
- この変更は、対象外の手動書式・別シートの保持を保証しません。保存先選択、OneDrive・SPO同期方法も変更していません。

詳しい移行手順は [docs/_archive/入車時間マスタ_SPO移行手順.md](docs/_archive/入車時間マスタ_SPO移行手順.md) を参照してください。

## 起動

最短手順はプロジェクト直下の [run_ch_kanban.bat](run_ch_kanban.bat) をダブルクリックする方法です。

手動起動する場合は次を使います。

```powershell
conda run -n DIG_new python -m src.app.gui
```

exe作成と配布手順は [docs/起動・exe化ガイド.md](docs/起動・exe化ガイド.md) を参照してください。

## プロジェクト構造

```
src/
  models/      定数・データ型
  utils/       正規化・CSV/Excel ユーティリティ
  services/    仕分け・工程割当・エクスポート（spo_export含む）
  app/         GUI (CustomTkinter)
qt_setboard/   PySide6/QML 版セットボード（別系統）
config/        旧設定等（現行の個人設定は利用者領域へ保存）
tests/         ユニット・結合テスト
docs/          要件定義・アーキテクチャ
prompts/       AI開発支援プロンプト（要点は CLAUDE.md に統合）
```

## 元プロジェクトとの主な違い

| 項目 | かんばん自動仕分け | CHかんばんセット |
|------|---------------------|------------------|
| 作業者数 | 複数 (4工程) | **1人** (メイン/リリーフ/あふれの3レーン) |
| 工程 | 1工程〜4工程 | メイン / リリーフ / あふれ |
| 締切超過時 | 次工程へ | リリーフ工程へ、なお不可は**あふれ工程** |
| セットボード | 別ウィンドウ中心 | タブ内の3レーン表示 |

## 運用ルール

機能追加・修正をコミットする際は、必ず gui.py 冒頭の APP_VERSION も今回の日付・コミット要約に更新してからコミットする。更新を忘れるとステータスバーの表示が古いままになり、実働PCで最新化されているかの確認ができなくなる。
