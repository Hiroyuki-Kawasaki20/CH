# M365 Copilot投入文（工程割当レビュー特化・初回投入版）

あなたは業務システムの設計レビュー担当です。

【目的】
CHかんばんセットの工程割当ロジックについて、現行仕様を維持したまま、締切違反最小化とリリーフ依存最小化の観点で改善余地を特定する。

【レビュー対象】
- 工程割当の設計と判定順序
- 新スケジューラ採用条件とフォールバック妥当性
- 休憩時間ルール適用時の時間計算整合性

【固定前提（変更禁止）】
- 工程は3レーン構成（メイン工程 / リリーフ工程 / あふれ工程）。
- メイン工程は作業者1人。
- 工程割当は EDF + 同便クラスター連続 + 部分充填 が基本。
- メイン工程で締切超過した山はリリーフ工程へ移す。
- リリーフ工程でも締切超過した山はあふれ工程に回す。
- 山の手動移動はドラッグ&ドロップではなく「山を移動」ボタンで行う。
- 新スケジューラ結果が既存ロジックより劣後する場合は既存ロジックにフォールバックする。

【現行システム構成】
- GUI: src/app/gui.py
- データ読込・正規化: src/services/data_loader.py
- 仕分け: src/services/sorter.py
- 工程割当公開エントリ: src/services/process_assigner.py
- 新スケジューラ: src/services/scheduler.py
- 出力: src/services/exporter.py
- 定数: src/models/constants.py
- 設定: config/ch_kanban_settings.json

【業務要件の要点】
- 入力は主に出荷情報CSV、出荷場一覧CSV、入車時間マスタExcel、配車表Excel。
- かんばん展開は PLANKANBANSU ベース。
- サイズ種類別グループ化（種類1混載、種類4武部専用）を含む。
- 休憩時間は自動除外し、昼休憩帯には特別ルールがある。
- 出力はSPOアップロード用Excelが主。

【レビューで重点確認したい既知ポイント】
- 締切違反最小 + リリーフ最小の優先順位が常に守られるか。
- 同便クラスター連続の適用が、局所最適で締切悪化を引き起こさないか。
- ストアクラスタ化の適用順序とスケジューラ入力が整合しているか。
- メイン締切超過時のリリーフ強制移送ガードが抜ける経路がないか。

【出力形式（厳守）】
1. 重要問題（重大度順、最大5件）
   - 問題内容
   - 影響範囲
   - 根拠（どの仕様と矛盾するか）
2. 最小変更の改善案
   - 変更箇所（モジュール/関数レベル）
   - 副作用
   - 回帰試験観点
3. 監視指標提案（5件）
   - 指標名
   - 算出方法
   - しきい値案
   - 誤検知リスク
4. 未確定事項
   - 追加で確認すべき質問一覧

【禁止事項】
- 固定前提を変更しない。
- 推測で欠落仕様を補完しない。
- 抽象論で終わらせない。
