## torchが不要と判断した根拠・解析経路

1. `src`全PythonファイルをASTで確認。関数内の遅延importを含めtorch参照なし。`__import__`、`import_module`、`entry_points`、`load_entry_point`、`exec`、`eval`による動的ロードもなし。プラグイン読込みも見つからない。
2. 標準`requirements.txt`・`environment.yml`はtorchを要求しない。**環境全体の`environment-full.yml`にはtorch 2.10.0／torchvision 0.25.0が含まれる**が、アプリで使用する根拠にはならない。pandas・NumPy・openpyxl・CustomTkinterのインストール済みメタデータにもtorch要求なし。
3. specの`hiddenimports`は空、データ収集はCustomTkinterの`assets/**/*`のみ。spec自体は`collect_submodules`を呼ばない。
4. 前回ログはpandas → SciPy → pytest → setuptools等のフック処理を経て、直前の`hook-pycparser.py`の後に`hook-torch.py`へ到達。torchフック内の`collect_submodules("torch")`がOpenMP Error #15で異常終了した。**このINFOログの並びだけでは、pycparser等がtorchを直接importしたとは断定できない。**
5. 今回の成功ビルドが生成したxrefでは、torchは`ExcludedModule`。参照元は`scipy._lib.array_api_compat.common._helpers`および`scipy._lib.array_api_compat.torch`の`_aliases`・`_info`・`_typing`と確認できた。SciPy側には`TYPE_CHECKING`配下やtorch Tensorを扱う場合の任意importがある。今回のアプリはpandas/NumPyを使用し、torch Tensorを生成・入力する経路はない。
6. torchを`MetaPathFinder`でimport不可にした隔離プロセスで、GUIモジュールのimportとCSV/マスタ・SPO出力・マスタ解決・締切回帰テスト74件が成功。torchのimport試行は0件。実GUIや本番入力は使用していない。
