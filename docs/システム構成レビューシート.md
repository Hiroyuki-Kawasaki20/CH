# システム構成レビューシート（1ページ）

作成日: 2026-06-16  
対象システム: CHかんばんセット  
版数: v0.1

---

## 1. システムの目的（3行で要約）
- 目的: CH受入のかんばん仕分けと工程割当を自動化し、締切遅延を最小化する。
- 利用者: 現場オペレーター、運用担当、管理者。
- 想定利用シーン: 日次の仕分け実行、セットボード確認、SPOアップロード。

## 2. 現在の構成（要点のみ）
- 実行環境: Windows ローカルPC + Python/conda
- フロントエンド: CustomTkinter GUI
- バックエンド: Pythonロジック（仕分け・工程割当・出力）
- データ: CSV/Excel（出荷情報、出荷場一覧、入車時間マスタ）
- 外部連携: SPO用Excel出力、Power Apps表示
- 監視/ログ: アプリ内ログ中心（要強化）
- バックアップ: 運用依存（要標準化）

簡易構成:
ユーザー -> GUIアプリ -> 仕分け/割当エンジン -> CSV/Excel入出力 -> SPO/Power Apps

## 3. 現状評価（5段階）
- 機能要件達成度: 4
- セキュリティ: 2
- 可用性/障害対策: 2
- 性能/スケーラビリティ: 3
- 運用容易性: 2

総評:
業務ロジックは高い完成度だが、非機能要件（セキュリティ・可用性・運用統制）の設計が不足。

## 4. 主なリスク（上位5件）
1. 単一PC依存による停止リスク（実質SPOF）
2. 入力ファイル改ざん/誤更新の検知不足
3. 監査証跡不足（誰がいつ何を実行・変更したか）
4. 障害時復旧手順の未標準化（RTO/RPO未定義）
5. データ量増時の性能劣化リスク

## 5. 改善案（短期/中期）
短期（2-4週間）:
- 入力スキーマ検証の導入（必須列・型・値域チェック）
- 監査ログの整備（実行者、入力条件、出力結果、エラー理由）
- バックアップ/リストア手順書の作成と月1回の復旧演習

中期（1-2か月）:
- 仕分けエンジンの分離（GUIと実行ロジックを疎結合化）
- 権限分離（実行、設定変更、承認）
- 性能試験基準の策定（最大データ量、許容時間、閾値）

## 6. 優先度付き次アクション
P0（今週）:

3. バックアップ対象と保管世代を確定（設定、マスタ、成果物、ログ）
