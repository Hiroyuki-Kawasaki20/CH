# CHかんばんセット 仕分け・割り振りルール

この文書は、CHかんばんセットで実際に適用される仕分け・工程割り振りロジックを、運用者向けに明文化したものです。
実装基準は `src/services/sorter.py`、`src/services/scheduler.py`、`src/services/process_assigner.py` です。

## 1. 対象と前提

- 対象: 便名・受入・オーダーで絞り込んだ出荷情報
- 1レコードは `PLANKANBANSU` 分だけ展開され、1行=1パレットとして扱う
- 山の高さ上限は 2450mm
- セットボードはメイン・リリーフ・あふれの3レーン表示
- 引取工数の計算式:

```text
引取工数(秒) = Max移動工数 + 187.64 + (パレット数 - 1) * 3.247 + パレット数 * 52
```

## 2. 仕分けルール

### 2.1 共通ルール

- 入車時間マスタがある場合、各行に「入車時間」を付与する
- 基本はファーストフィット(上から順に積む)で山を作る
- 入車時間が異なるパレットは同一山にしない(同一サイズ種類内で入車時間ごとに独立積み)

### 2.2 サイズ種類ごとの扱い

- サイズ種類 1:
  - 便ごとにローカル山を作成後、混載を行う
  - 混載は最大3山まで
- サイズ種類 4:
  - 入車時間あり: 入車時間単位で再積み
  - 入車時間なし: 便番号単位で再積み
- その他サイズ:
  - 基本グループ単位で山通番を採番

### 2.3 サイズ種類1の混載条件

- 混載候補は高さ上限 2450mm 以内で選ぶ
- 原則: 同一納入先で便番号が異なる組み合わせは混載禁止
- 例外: 納入先が `KVC` または `元町` で始まり、かつ入車時間が一致する場合は、便番号が異なっても同一山への混載を許可
- 納入先の正規化（例: `TMK` → `KVC`）は山結合判定の前に行う。したがって、統合例外判定は正規化後の納入先で評価される
- 2山混載を確定後、余裕があれば3山目を追加
- 混載キー列(既定: `UKEIRE`)は集計用。混載可否判定自体は「納入先×便番号差異」で判定

### 2.4 混載後の救済分割(競合解消)

サイズ種類1の混載後、次の条件を満たす山は分割対象:

- その山に含まれる便の最小締切(入車-10分)が
- その山に必要な最大開始下限(前便入車+10分)より早い

このとき、山内で最も締切が厳しい納入先を別山へ分離し、締切違反を回避する。

## 3. 山統合ルール

- サイズ種類1(混載済み)の山通番を先に確定
- その後、サイズ種類4とその他サイズを後続番号で連番採番
- 最終的な山通番は、山構成を変えずに「オーダー番号(NONYUHIBIN末尾2桁)昇順 → 同一オーダー内はサイズ種類順」で再採番する（この採番は、便集荷順・リリーフ挿入を含む工程最適化ロジックとは独立）
- 最終明細は山通番昇順、同一山内は移動工数降順

### 3.1 山内パレット（GroupedData）の番号採番ルール

SPOアップロード用 GroupedData の「番号」列は **移動工数の昇順** で 1, 2, 3 … と採番する。

- 第1キー: 移動工数 昇順（数値比較）
- 第2キー（同値安定化）: SEBANGO 昇順。SEBANGO 列が存在しない場合は 工程内No 昇順。
- 移動工数が NaN のパレットは末尾（番号最大）とする。
- 移動工数列が存在しない山は全行 NaN 扱いとなり、入力順（DataFrame の行順）で採番する。
- SPOアップロード用の「引取開始時間」は、GroupedData 内の候補便のうち最も早い開始候補を採用する。
- 便が 1直・2直にまたがっていても、深夜側の候補を優先して上書きしない。

実装箇所: `src/services/exporter.py` — `build_groupeddata_json_for_mountain()`

> **検証例（06便 NONYUHIBIN=2026070110）**
> | ストア | 移動工数 | 番号 |
> |---|---|---|
> | Q10-B-7  | 72.908（最小） | 1 |
> | Q10-A-11 | 72.911         | 2 |
> | Q10-A-12 | 72.912         | 3 |

## 4. 割り振り(メイン/リリーフ)ルール

### 4.0 割り振りエンジンの採用ルール

- まず新スケジューラ（EDF + 同便クラスター連続 + アイドル部分充填）で割付を作成する
- 次に既存ロジックの結果と比較し、目的関数が同等以上のときのみ新スケジューラ結果を採用する
- 目的関数が劣る場合は既存ロジック結果を採用する（後方互換）

### 4.1 用語

- メイン工程: 原則1人で処理する主工程
- リリーフ工程: メインで締切に間に合わない山の退避先
- 各直始業時間: 1直=06:25、2直=16:40
- 引取り可能時間: 入車時間マスタの「入車時間」(納入先×便で紐づく時刻)
- 締切: 引取り可能時間 - 10分(= 入車時間 - 10分)
- 開始下限: その山を開始できる最も早い時刻

引取り可能時間の補足:

- 00:00〜1直開始前(06:25前)の時刻は、運用日タイムライン上で +24時間として扱う
  - 例: 00:20 は 24:20 として評価し、23:xx からの連続性を保つ

### 4.2 開始下限の決め方

- マスタに「セットありフラグ」列がない場合(旧マスタ):
  - 従来ルールを適用
- セットありフラグ=true:
  - 目的: 次直の開始時刻からでは間に合わない便を、前直で準備開始するためのフラグ
  - 同レーンの直前便を基準にする
  - 同レーンの直前便は `参照先オーダー = 対象オーダー - レーン数` で計算する
  - レーン数は品目で固定（変動しない）
    - 日野: 2
    - その他: 1
  - 参照先が先頭側に突き抜ける場合は、同レーンの最終便へ循環して参照する
  - 開始下限は「参照先の入車時間 + ARRIVAL_BUFFER_SECS（10分）」
- セットありフラグ=false:
  - 日野(2レーン)は同レーン直前便(N-2)を参照する
  - 参照時刻が 24:xx/25:xx でも前日側をそのまま採用せず、当日基準に戻したうえで下限を適用する
  - 開始下限は必ず「各直開始 + 15分」を max で適用する
    - 1直の1便目: 06:40以降
    - 2直の1便目: 16:55以降
  - 非日野は従来どおり前便入車+10分

補足:

- 引取開始時刻のバッファは 10分(600秒) を用いる
- 本実装では `ARRIVAL_BUFFER_SECS` がこの定数に対応する

従来ルール(前便入車+10分)の詳細:

- 納入先が武部:
  - 同納入先内で1つ前の入車時間グループ +10分
- その他納入先:
  - 原則、前便番号の入車時刻 +10分
- 日野系納入先:
  - 01便の前便を最終便として循環扱い(例: 11 -> 01)
- 前便が引けない場合:
  - 開始制約なし(0秒)

### 4.3 締切の補正(セットあり便)

セットありフラグ=true の便は、通常締切(入車-10分)に加えて、
直ごとのメイン工程上限を下限として締切を補正する。

- 1直: 15:20
- 2直: 25:35(翌01:35)

実効締切 = max(入車-10分, 上記上限)

### 4.4 メイン工程への割り振り

1. 未割当山から、締切が最も早い山を主対象として選ぶ
2. 主対象を遅らせない範囲で、先に処理可能な山があれば前倒し採用
3. メインに置いたときに終了時刻 <= 締切ならメイン確定
4. 超過する場合はリリーフへ回す

### 4.5 リリーフ工程への割り振り

- 1山目:
  - 最遅開始(締切に間に合う時刻)と開始下限の両方を満たす時刻で開始
- 2山目以降:
  - max(前山終了, 開始下限) から開始

### 4.6 休憩・照合ルール

- 開始時刻が休憩中、または作業が休憩をまたぐ場合は休憩終了+1分へ繰り下げ
- 昼休憩（10:40-11:25, 20:55-21:40）は特別ルールを適用
  - 休憩前最後の山は休憩開始10分前までに完了
  - 休憩後最初の山は休憩終了15分後から開始
- 照合180秒は工程ごとに独立して付与
- 3山目、5山目、7山目... の開始前に180秒を加算

休憩時間:

- 1直: 08:30-08:40, 10:40-11:25, 12:55-13:05
- 2直: 18:45-18:55, 20:55-21:40, 23:10-23:20

### 4.7 あふれ工程

- メイン工程・リリーフ工程のいずれでも締切に収まらない山は、あふれとして扱う
- あふれはセットボード上の警告・手動確認用のレーンに表示する
- 出力上は工程区分として残し、後工程で再調整できるようにする
- ただし、山を「納入先×便」の作業単位に仮分割すればリリーフで完了可能な場合は、あふれ化せず救済する

### 4.8 直選択と連続実行時の引継ぎ

- 実行時に対象の直（1直 / 2直）を選択する
- 引継ぎ時刻は「前回実行と同一直」の場合のみ適用する
  - 同一直: 前回の工程別終了時刻を次回の開始下限として利用
  - 直切替: 引継ぎを使わず、当該直の基準時刻で初回扱いで再計算
- 手動で引継ぎを無効化したい場合は「引継クリア」を使用する
- アプリ再起動後は引継ぎ情報は保持されない

## 5. 後処理(時刻の再調整)

### 5.1 メイン工程のT0シフト

- 開始下限で固定されていないメイン山のみ対象
- 全山が締切を満たす範囲で、全体を同一量(T0)だけ後ろへシフト
- 目的: 実運用に近い時刻帯へ寄せる

### 5.2 安全弁

- メイン工程に締切超過が残る場合:
  - まずメイン内を締切優先順で再スケジュール
  - それでも遅れる山はリリーフへ再振り分け

### 5.3 リリーフ最小化

- 再スケジュール後、締切を守ったままメインへ戻せる山を再昇格
- 最終的に「締切違反最小 + リリーフ最小」を目標に収束させる

## 6. 運用上の確認ポイント

- 入車時間マスタの納入先名と便番号が正規化後に一致しているか
- セットありフラグ列の有無で開始下限ルールが変わる点を認識しているか
- 日野系の便循環(最終便->01便)を想定したマスタになっているか
- 締切違反が発生した場合、救済分割またはリリーフ再振分けの結果を確認する
- 「入車時間マスタ.xlsx から直接取込」ボタンを使う場合、xlsx ファイルの列構成（セクション8参照）を事前に確認する
- セットありフラグは画面上で ☑/☐ 表示される。保存時に ☑→"1"、☐→"" に変換されることを把握しておく

## 8. マスタ管理UI仕様（修正③ 追加機能）

### 8.1 入車時間マスタ.xlsx 直接取込ボタン

**場所:** マスタ管理タブ — 上部ボタン列の右端「入車時間マスタ.xlsx から直接取込」（緑色）

**操作手順:**

1. ボタンをクリックする
2. 確認ダイアログ（「既存の表示内容を全置換します」）で **はい** を選ぶ
3. `get_master_path()` が返す既定パスの xlsx を自動的に読み込む（ファイル選択ダイアログは開かない）
4. マスタ一覧が取込内容で全置換され、画面に反映される

**取込ファイル仕様:**

| 列名 | 型 | 説明 |
|---|---|---|
| `OData_納入先` | 文字列 | 納入先名（正規化前の生の値で可） |
| `NONYUHIBIN` | 文字列/数値 | 便番号（2桁ゼロ埋めに正規化） |
| `入車時間` | 文字列 | HH:MM 形式の時刻 |
| `セットありフラグ` | 文字列/数値 | "1" または "" / 0 も許容（後述の変換ルール参照） |

**注意:**
- 取込は全置換。取込前の手動編集内容は消えるため、必要な場合は先に「マスタ保存」を行うこと
- 上記4列以外の余分な列は無視される
- `get_master_path()` の既定パス外にファイルがある場合は、従来の「全受入CHからインポート」ボタンを使うか、ファイルを既定パスにコピーしてから取込むこと

**実装箇所:** `src/app/gui.py` — `import_from_master_xlsx()`、`src/services/data_loader.py` — `load_pickup_time_master_xlsx()`

### 8.2 セットありフラグの UI 仕様

#### 表示形式

マスタ一覧の「セットありフラグ」列は **チェックボックス記号** で表示する。

| 画面表示 | 内部保存値 | 意味 |
|---|---|---|
| `☑` | `"1"` | セットあり（ON） |
| `☐` | `""` (空文字) | セットなし（OFF） |

#### 既存値の正規化ルール

- xlsx やダイアログ入力で `"0"` が渡された場合: **OFF（☐/"" ）** として扱う
- `"1"` または `"true"` 相当の値: **ON（☑/"1"）** として扱う
- それ以外の非空文字列: OFF として扱う（`src/services/data_loader.py` — `_is_truthy_set_flag()` で判定）

> **変換フロー（画面↔保存）**
> ```
> xlsx 読込 / 入力  →  set_flag_value_to_checkbox_mark()  →  画面表示（☑/☐）
> 画面表示（☑/☐）  →  checkbox_mark_to_set_flag_value()  →  内部保存値（"1"/""）
> ```

#### 画面操作

- マスタ一覧の「セットありフラグ」セル（第4列）をクリックするだけで ☑ ⇔ ☐ をトグルできる
- ダブルクリックで「行編集」ダイアログを開いた場合、セットありフラグは `1/0` の文字列で入力する（保存時に自動変換される）

#### process_assigner.py への影響

このフラグは `src/services/process_assigner.py` の `_legacy_assign_processes_by_arrival_time()` 内で参照され、**開始下限の計算ルール** を切り替える。

| セットありフラグ | 開始下限ルール | 締切補正 |
|---|---|---|
| マスタ列自体が存在しない（旧マスタ） | 従来ルール（前便入車 +10分）を全便に適用 | なし |
| `false`（☐ / `""`） | 各直の1便目: 直開始 +15分 / それ以外: 前便入車 +10分 | なし |
| `true`（☑ / `"1"`） | 従来ルール（前便入車 +10分） | あり（直ごとの上限で実効締切を補正。詳細は 4.3 節） |

実装箇所: `src/services/process_assigner.py` — `set_flag_map` 構築（371〜373行付近）、`set_flag` 参照（521行付近）
