# CHかんばんセット 仕分け・割り振りルール

この文書は、CHかんばんセットで実際に適用される仕分け・工程割り振りロジックを、運用者向けに明文化したものです。
実装基準は `src/services/sorter.py`、`src/services/scheduler.py`、`src/services/process_assigner.py` です。

## 1. 対象と前提

- 対象: 便名・受入・オーダーで絞り込んだ出荷情報
- 1レコードは `PLANKANBANSU` 分だけ展開され、1行=1パレットとして扱う
- 山の高さ上限は 2450mm
- セットボードはメイン・リリーフ・あふれの3レーン表示
- 引取工数の計算式:

```text
引取工数(秒) = Max移動工数 + 187.64 + (パレット数 - 1) * 3.247 + パレット数 * 52
```

## 2. 仕分けルール

### 2.1 共通ルール

- 入車時間マスタがある場合、各行に「入車時間」を付与する
- 基本はファーストフィット(上から順に積む)で山を作る
- 入車時間が異なるパレットは同一山にしない(同一サイズ種類内で入車時間ごとに独立積み)

### 2.2 サイズ種類ごとの扱い

- サイズ種類 1:
  - 便ごとにローカル山を作成後、混載を行う
  - 混載は最大3山まで
- サイズ種類 4:
  - 入車時間あり: 入車時間単位で再積み
  - 入車時間なし: 便番号単位で再積み
- その他サイズ:
  - 基本グループ単位で山通番を採番

### 2.3 サイズ種類1の混載条件

- 混載候補は高さ上限 2450mm 以内で選ぶ
- 同一納入先で便番号が異なる組み合わせは混載禁止
- 2山混載を確定後、余裕があれば3山目を追加
- 混載キー列(既定: `UKEIRE`)は集計用。混載可否判定自体は「納入先×便番号差異」で判定

### 2.4 混載後の救済分割(競合解消)

サイズ種類1の混載後、次の条件を満たす山は分割対象:

- その山に含まれる便の最小締切(入車-10分)が
- その山に必要な最大開始下限(前便入車+10分)より早い

このとき、山内で最も締切が厳しい納入先を別山へ分離し、締切違反を回避する。

## 3. 山統合ルール

- サイズ種類1(混載済み)の山通番を先に確定
- その後、サイズ種類4とその他サイズを後続番号で連番採番
- 最終明細は山通番昇順、同一山内は移動工数降順

## 4. 割り振り(メイン/リリーフ)ルール

### 4.0 割り振りエンジンの採用ルール

- まず新スケジューラ（EDF + 同便クラスター連続 + アイドル部分充填）で割付を作成する
- 次に既存ロジックの結果と比較し、目的関数が同等以上のときのみ新スケジューラ結果を採用する
- 目的関数が劣る場合は既存ロジック結果を採用する（後方互換）

### 4.1 用語

- メイン工程: 原則1人で処理する主工程
- リリーフ工程: メインで締切に間に合わない山の退避先
- 各直始業時間: 1直=06:25、2直=16:40
- 引取り可能時間: 入車時間マスタの「入車時間」(納入先×便で紐づく時刻)
- 締切: 引取り可能時間 - 10分(= 入車時間 - 10分)
- 開始下限: その山を開始できる最も早い時刻

引取り可能時間の補足:

- 00:00〜1直開始前(06:25前)の時刻は、運用日タイムライン上で +24時間として扱う
  - 例: 00:20 は 24:20 として評価し、23:xx からの連続性を保つ

### 4.2 開始下限の決め方

- マスタに「セットありフラグ」列がない場合(旧マスタ):
  - 従来ルールを適用
- セットありフラグ=true:
  - 従来ルール(前便入車+10分)を適用
- セットありフラグ=false:
  - 各直の1便目は「直開始 + 15分」
    - 1直の1便目: 06:40以降
    - 2直の1便目: 16:55以降
  - それ以外は前便入車+10分

従来ルール(前便入車+10分)の詳細:

- 納入先が武部:
  - 同納入先内で1つ前の入車時間グループ +10分
- その他納入先:
  - 原則、前便番号の入車時刻 +10分
- 日野系納入先:
  - 01便の前便を最終便として循環扱い(例: 11 -> 01)
- 前便が引けない場合:
  - 開始制約なし(0秒)

### 4.3 締切の補正(セットあり便)

セットありフラグ=true の便は、通常締切(入車-10分)に加えて、
直ごとのメイン工程上限を下限として締切を補正する。

- 1直: 15:20
- 2直: 25:35(翌01:35)

実効締切 = max(入車-10分, 上記上限)

### 4.4 メイン工程への割り振り

1. 未割当山から、締切が最も早い山を主対象として選ぶ
2. 主対象を遅らせない範囲で、先に処理可能な山があれば前倒し採用
3. メインに置いたときに終了時刻 <= 締切ならメイン確定
4. 超過する場合はリリーフへ回す

### 4.5 リリーフ工程への割り振り

- 1山目:
  - 最遅開始(締切に間に合う時刻)と開始下限の両方を満たす時刻で開始
- 2山目以降:
  - max(前山終了, 開始下限) から開始

### 4.6 休憩・照合ルール

- 開始時刻が休憩中、または作業が休憩をまたぐ場合は休憩終了+1分へ繰り下げ
- 昼休憩（10:40-11:25, 20:55-21:40）は特別ルールを適用
  - 休憩前最後の山は休憩開始10分前までに完了
  - 休憩後最初の山は休憩終了15分後から開始
- 照合180秒は工程ごとに独立して付与
- 3山目、5山目、7山目... の開始前に180秒を加算

休憩時間:

- 1直: 08:30-08:40, 10:40-11:25, 12:55-13:05
- 2直: 18:45-18:55, 20:55-21:40, 23:10-23:20

### 4.7 あふれ工程

- メイン工程・リリーフ工程のいずれでも締切に収まらない山は、あふれとして扱う
- あふれはセットボード上の警告・手動確認用のレーンに表示する
- 出力上は工程区分として残し、後工程で再調整できるようにする
- ただし、山を「納入先×便」の作業単位に仮分割すればリリーフで完了可能な場合は、あふれ化せず救済する

## 5. 後処理(時刻の再調整)

### 5.1 メイン工程のT0シフト

- 開始下限で固定されていないメイン山のみ対象
- 全山が締切を満たす範囲で、全体を同一量(T0)だけ後ろへシフト
- 目的: 実運用に近い時刻帯へ寄せる

### 5.2 安全弁

- メイン工程に締切超過が残る場合:
  - まずメイン内を締切優先順で再スケジュール
  - それでも遅れる山はリリーフへ再振り分け

### 5.3 リリーフ最小化

- 再スケジュール後、締切を守ったままメインへ戻せる山を再昇格
- 最終的に「締切違反最小 + リリーフ最小」を目標に収束させる

## 6. 運用上の確認ポイント

- 入車時間マスタの納入先名と便番号が正規化後に一致しているか
- セットありフラグ列の有無で開始下限ルールが変わる点を認識しているか
- 日野系の便循環(最終便->01便)を想定したマスタになっているか
- 締切違反が発生した場合、救済分割またはリリーフ再振分けの結果を確認する

## 7. 変更管理

- 本ルールを変更する場合は、次の3点を同時に更新すること
  - この文書
  - `src/services/sorter.py`
  - `src/services/process_assigner.py`
