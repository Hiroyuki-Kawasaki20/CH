## 原因調査

### 実体とインストーラ情報の不一致

- Python：`C:\Users\1588386\.conda\envs\DIG_new\python.exe`、3.11.14、64bit。直接実行。
- PyInstaller：6.22.3、hooks-contrib：2026.9。`is_conda`・`is_pure_conda`はTrue。
- NumPy：`importlib.metadata`上2.3.4、`get_installer('numpy') == 'pip'`。一方`numpy.show_config()`はBLAS/LAPACKを`mkl-sdl`、version 2025と報告。主要PYDも`mkl_rt.2.dll`を直接importする。
- conda-meta側のnumpy/numpy-baseは2.3.5。この環境ではpip/condaの記録が混在しているが、今回更新・削除で修復はしない。
- 標準`PyInstaller/hooks/hook-numpy.py`はinstallerが`conda`の場合だけ`conda_support.collect_dynamic_libs('numpy', dependencies=True)`を呼ぶ。その分岐に入らず、MKLの動的DLLが収集されなかった。
- SciPy 1.17.1はpip導入で、`scipy.show_config()`はOpenBLAS 0.3.30を報告。標準`hook-scipy.py`のdelvewheel収集を変更していない。

### 前回の収集とDLL探索

前回の`Analysis-00.toc`・`COLLECT-00.toc`には、mkl-serviceのPYDと`mkl_rt.2.dll`のみがあった。MKL dispatcherは存在したが、実行時に読み込む`mkl_intel_thread.2.dll`・`mkl_core.2.dll`等とIntel OpenMPが欠落していた。

既存のpefile 2024.8.26でPE importとdelay importを確認した。`mkl_rt.2.dll`・`mkl_intel_thread.2.dll`・`mkl_core.2.dll`の静的importは`KERNEL32.dll`だけで、delay importも空。**動的LoadLibrary先はPE表だけでは確定できない**ため、単なる静的依存追加では足りない。

`libiomp5md.dll`のPE importはKERNEL32・VCRUNTIME140・UCRT API群。Windows提供DLLと、配布フォルダへ同梱されるVC/UCRT runtimeを区別した。今回の実起動・計算でMKL/OpenMPのロード元まで確認して探索結果を検証した。

## 採用した収集方式

標準の`PyInstaller.utils.hooks.conda_support.collect_dynamic_libs`を利用する。独自にLibrary/bin全体を走査・コピーする方式ではない。

- `mkl`と`intel-openmp`をそれぞれ`dependencies=False`で取得し、必要なCPU実行DLLの許可リストへ限定。
- `dependencies=True`ではTBB、hwloc、libxml等まで含む96 DLLになったため不採用。MPI・TBB・GPU・OpenMPデバッグ用DLLは追加しない。
- DLL取得元は`sys.prefix/Library/bin`。標準APIが使う現在環境のcondaメタデータに基づく。個人絶対パスはspec/フックへ埋め込まない。
- 必須DLLの欠落・他環境パス・同名異ソース・ライセンス/通知欠落はビルドエラーにする。同一ソース重複は1件にまとめる。
- `hook-mkl.py`を専用`build_hooks`へ追加し、specの`hookspath`へ登録。NumPy/SciPy標準フックを置き換えず、mkl-service解析時の収集だけを補完する。
- 配置先はPyInstaller 6 onedirの`_internal`直下。システムフォルダへのコピーや実行時のconda PATH参照は不要。
- `torch`除外とCustomTkinter assets収集は維持。
- Intelバイナリ無改変条件のため、COLLECTのUPX除外へ`mkl_*.dll`・`libimalloc.dll`・`libiomp5md.dll`を追加。完成品のSHA-256で無改変を検証した。

## ライセンス確認

### MKL

conda package `mkl 2025.0.0`のメタデータと同梱本文はIntel Simplified Software License (October 2022)で一致。バイナリ無改変での利用・再配布と、著作権/条件の再掲、名称による推奨表示禁止等の条件を確認した。

### Intel OpenMP：未解決事項あり

`intel-openmp 2025.0.0`のメタデータは`LicenseRef-IntelSimplifiedSoftwareOct2022`だが、実際の同梱本文は**Intel Developer Tools EULA (August 2024)**。EULA第1条Iはredist一覧にあるファイルを再配布対象と定義し、第2.1.Dは製品の一部としてのバイナリ配布や逆コンパイル等を禁じる契約条件を求める。

ローカル資料で対象DLLのredist一覧を確認できず、Intel公式の2025版候補URLも取得時404となった。**本文・通知を同梱しただけで再配布条件を満たしたとは断定しない。** 正式配布前に対象バージョンの許諾と社内ライセンス判断を確認する。

### 同梱資料と取得元

- 現在環境の`conda-meta`が示す`link.source/info/licenses`から、MKL・OpenMPの`license.txt`と`tpp.txt`を取得。
- 環境内`share/doc/mkl/licensing`と`share/doc/compiler/licensing/openmp`の第三者通知も取得。
- 計13ファイルを`_internal/licenses/mkl`・`_internal/licenses/intel-openmp`配下へ原文のまま同梱。元の文字コード・バイト列を変更せず、全ファイルのSHA-256一致を確認。
- パッケージキャッシュのライセンス原本が消えている場合も、通知を省略してビルド成功にせず明示エラーとする。
- TBB等の追加ライセンスを要するDLL群は今回の独自収集対象にしていない。他の既存同梱依存を含む製品全体の法務監査を完了したという意味ではない。
