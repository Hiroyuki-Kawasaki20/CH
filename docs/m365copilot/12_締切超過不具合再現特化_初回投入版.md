# M365 Copilot投入文（締切超過不具合再現特化・初回投入版）

あなたは業務システムの不具合解析担当です。

【目的】
CHかんばんセットにおける締切超過関連不具合を、再現可能な手順として整理し、原因候補と最小変更の対策を提示する。

【事象サマリ】
- 発生カテゴリ: 締切超過判定の過大発生 / 誤分類（メイン→リリーフ→あふれ）
- 優先度: 高
- 期待結果: 締切に間に合う山はメインまたはリリーフに収まり、不要なあふれを発生させない。
- 実際結果: 一部ケースで、締切に間に合う可能性がある山が早期にリリーフ/あふれへ押し出される疑いがある。

【再現条件の初期仮定】
- 条件A: 武部データを含み、前便グループが存在しないケース。
- 条件B: 休憩帯の前後にまたがる山を含むケース。
- 条件C: 同便クラスター連続が強く効くケース（締切が近い別便が混在）。
- 条件D: ストアクラスタ化後に山マージ明細が多いケース。

【固定仕様（変更禁止）】
- 3レーン構成（メイン / リリーフ / あふれ）。
- メイン工程1名。
- EDF + 同便クラスター連続 + 部分充填。
- メインで締切超過ならリリーフ、リリーフでも超過ならあふれ。
- 新スケジューラ劣後時は既存ロジックへフォールバック。

【既知の注意点（再発確認対象）】
- 武部で前便グループなしの場合、start_floor は 0（制約なし）が正。
- 最適化スコアは締切違反最小を最優先し、その次にリリーフ最小を重視。
- GUI側でクラスタ化適用順序がズレるとスケジューラ入力が変質する。

【解析対象モジュール】
- src/app/gui.py
- src/services/sorter.py
- src/services/process_assigner.py
- src/services/scheduler.py
- src/services/exporter.py

【依頼内容】
以下を、断定と推測を分離して示してください。

【出力形式（厳守）】
1. 原因仮説（確度: 高/中/低）
2. 最短再現手順（入力条件、操作、期待差分）
3. 切り分け手順（確認ログ、見るべき変数、分岐ポイント）
4. 暫定回避策（運用で即日できる方法）
5. 恒久対策（最小変更）
6. 追加テスト案
   - 単体テスト
   - 結合テスト
7. 未確定事項（質問）

【禁止事項】
- 仕様変更前提で結論を出さない。
- ログ未確認で原因を断定しない。
- 複雑な全面改修を第一案にしない。
