# M365 Copilot投入文（引き継ぎ向け日次運用手順書・初回投入版）

あなたは業務運用ドキュメント作成担当です。

【目的】
CHかんばんセットの日次運用を、引き継ぎ担当者がそのまま実行できる手順書として作成する。

【対象読者】
- 班長
- 実務担当者
- 引き継ぎ担当者（新任）

【システムの前提】
- 入力: 出荷情報CSV、出荷場一覧CSV、入車時間マスタExcel、配車表Excel
- 処理: 読込・正規化・フィルタ・かんばん展開・グループ化・工程割当
- 出力: SPOアップロード用Excel、未ヒット一覧CSV
- セットボード: メイン/リリーフ/あふれ 3レーン表示

【固定運用ルール（変更禁止）】
- メイン工程は1名。
- メインで間に合わない山はリリーフへ移す。
- リリーフでも間に合わない山はあふれ扱い（警告）にする。
- 山の手動移動は「山を移動」ボタンで行う。
- 休憩時間ルールを時間計算に反映する。

【手順書に必ず含める章】
1. 起動前確認
   - 必須ファイルの存在確認
   - 設定ファイル確認
   - 前日残件確認
2. 起動手順
   - 実行環境
   - 起動方法
   - 起動後の画面確認
3. 日次処理
   - データ取込
   - 便/受入/オーダー選択
   - 仕分け実行
   - セットボード確認
   - 出力作成
4. 監視ポイント
   - 締切違反
   - あふれ件数
   - 未ヒット一覧
5. 異常時対応
   - 入力欠損
   - マスタ未一致
   - 時刻異常
6. 手動介入
   - 山移動手順
   - 再計算手順
   - 再出力手順
7. 終了処理
   - 成果物保存
   - ログ保全
   - 引き継ぎ記録
8. 付録
   - 用語集
   - 問い合わせ先
   - 日次チェックリスト

【出力要件】
- 現場で読んで即実行できる記述にする。
- 各章に「目的」「操作」「確認結果」「異常時対応」を必ず入れる。
- チェックリストはチェックボックス形式にする。
- 判断基準は可能な限り数値か条件で示す。
- 不明点は確定文にせず、確認事項として最後に分離する。

【禁止事項】
- 現行仕様と矛盾する手順を書かない。
- 抽象的な精神論のみで章を埋めない。
- 不明点を伏せて断定しない。
