# M365 Copilot用テンプレート（不具合解析）

## 使い方
- 事象ごとにこのテンプレートを1回ずつ使う。
- ログや入力条件を必ず埋める。
- 回答には「再現手順」「暫定回避」「恒久対策」を分けて出させる。

## 貼り付けテンプレート
あなたは業務システムの不具合解析担当です。

【目的】
CHかんばんセットの不具合を、再現条件・原因・影響範囲・対策まで分解して特定する。

【事象サマリ】
- 発生日時:
- 事象:
- 期待結果:
- 実際結果:
- 優先度:

【再現条件】
- 便名:
- 受入:
- オーダー:
- 入力ファイル名:
- 特定メーカー/納入先条件: （例）武部
- 休憩帯のまたぎ有無:

【関連仕様（固定）】
- メイン工程で締切超過した山はリリーフへ移送。
- リリーフでも締切超過した山はあふれへ移送。
- 工程割当は EDF + 同便クラスター連続 + 部分充填。
- 新スケジューラが既存ロジックに劣後する場合はフォールバック。

【重点確認ポイント】
- 既存ロジックとの差分で悪化していないか。
- 休憩時間ルール適用の前後で時間計算が破綻していないか。
- 同便クラスター連続の適用で局所最適に陥っていないか。
- ストアクラスタ化や山マージ後の明細保持に欠落がないか。

【既知の注意点（再発確認）】
- 武部データで前便グループなしの場合、start_floor の扱いは 0 制約なしが正。
- 最適化評価は 締切違反最小 + リリーフ最小 を優先する。
- GUI側でクラスタ化適用位置がズレるとスケジューラ入力が変質する。

【対象モジュール】
- src/app/gui.py

【出力形式（厳守）】
1. 原因仮説（確度付き）
2. 最短再現手順
3. 切り分け手順（ログ/変数/分岐）
4. 暫定回避策
5. 恒久対策（最小変更）
6. 追加テスト（単体/結合）
7. 未確定事項（質問）

【禁止事項】
- 仕様を変更前提で結論を出さない。
- 変更案を複雑化しない。
- ログ未確認で断定しない。
