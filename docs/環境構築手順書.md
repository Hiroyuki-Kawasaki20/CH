# CHかんばんセット 共通配置・環境構築手順書（bat運用）

同じWindows PCを複数のWindowsアカウントで利用するための手順です。アプリのソース・batは共通配置し、Python環境・設定・終了時刻履歴・ログは利用者ごとに分けます。**今回はexeの使用・配布を行いません。**

- 配置例：`C:\Apps\CHKanban`（以下の例はこの場所を使用）
- Python：**3.11**（編集用PCでは3.11.14で確認）
- conda環境：各利用者本人の **DIG_new**
- 操作方法：[利用マニュアル.md](利用マニュアル.md)
- 業務ルール：[仕分け・割り振りルール.md](仕分け・割り振りルール.md)

## A. 管理者・更新担当者が1回行う共通配置

1. 承認済みのアプリ版を用意します。実データ、開発者の設定JSON、ログ、旧履歴、アーカイブを配布物へ混ぜないでください。
2. `C:\Apps\CHKanban` にソース一式を配置します。少なくとも `src/`、`scripts/start_ch_kanban.ps1`、`run_ch_kanban.bat`、`requirements.txt`、この手順書が必要です。
3. **利用者には読み取り・実行、更新担当者には更新に必要な権限**を設定します。全員へのフルコントロール付与は不要です。
4. 利用者から共通batと補助PowerShellスクリプトを実行できることを、組織の承認済みポリシーで確認します。実行が禁止される場合は管理者へ相談してください。セキュリティ製品の無効化・除外登録、実行ポリシーの回避は行いません。
5. 各利用者が使用するSPO上の入力フォルダ・出力フォルダを決め、同じ実体を案内します。URLやアクセス権は管理担当者が確認してください。

共通配置内の `config/ch_kanban_settings.json` やアプリ隣の旧設定は、通常起動では読み込みません。共通配置を利用者のデータ保存先として指定しないでください。

## B. 各Windowsユーザーが1回行う準備

### B-1. 本人のDIG_newを準備する

1. **実際にアプリを利用する本人のWindowsアカウント**でサインインします。
2. 組織の承認済み手順でcondaと本人専用のDIG_newを用意します。Python 3.11と `requirements.txt` のライブラリが必要です。導入・作成権限がない場合は担当者へ依頼します。
3. DIG_newは本人のホーム配下へ置きます。例：`C:\Users\<本人>\.conda\envs\DIG_new`。全ユーザー用condaが `C:\ProgramData` 等にあっても、DIG_new自体は本人用を使います。
4. condaの管理画面または承認済み端末で環境のフルパスを確認し、その中に `python.exe` と `conda-meta` フォルダがあることを確認します。他の人の環境やbase環境は指定しません。
5. Windowsの「環境変数」画面を開き、**本人のユーザー環境変数**へ以下を追加します（システム環境変数ではありません）。

| 名前 | 値 |
|---|---|
| `CH_KANBAN_ENV_PREFIX` | 本人のDIG_newフォルダの絶対パス。例：`C:\Users\<本人>\.conda\envs\DIG_new` |

値はフォルダまでとし、`python.exe` や引用符は含めません。同名DIG_newが複数あっても、この値で1つを明示します。共通batに個人パスを書き込まないでください。登録後は端末・ショートカット起動元を開き直します。反映しない場合はWindowsへ再サインインします。

**condaの選択規則：** `CONDA_EXE` が設定済みならそれを確認し、未設定なら本人ホーム・全ユーザー用領域の既知配置、最後にPATH上のcondaを調べます。本人ホーム外で許可する配置は `ProgramData` / `ProgramFiles` 領域です。他人のホーム配下のcondaは使用しません。特殊な配置で見つからない場合は担当者へ相談し、必要に応じて本人のユーザー環境変数 `CONDA_EXE` に承認済みcondaの絶対パスを指定します。

batは名前だけの `-n DIG_new` ではなく、明示したprefixを `conda run -p` に渡します。環境・conda・必須ライブラリが見つからなければ案内して終了し、baseやシステムPythonへ切り替えません。この改修作業でconda導入・環境作成・パッケージ更新は実施していません。

### B-2. 本人のOneDriveを準備する

1. 本人の業務アカウントでOneDriveへサインインします。
2. 管理担当者が案内した**同じSPO上の入力・出力フォルダ**に対して、「OneDriveへのショートカットの追加」を各自で行います。
3. エクスプローラで本人の同期先を開き、同期・必要ファイルのダウンロードが完了するまで待ちます。クラウド上だけの状態ではなく、ローカルから開ける状態にします。
4. 入力先には次を用意します。
   - `出荷情報_CH_最新版.csv`（ない場合は `出荷情報_全便_最新版.csv`）
   - `出荷場一覧.csv`
   - `入車時間マスタ.xlsx`
5. 出力先はSPO本体の監視先です。別の個人用フォルダと取り違えないよう、管理担当者とSPO上の実体を確認します。

各自のローカルパスは異なって構いません。共通なのはSPO上の入力・出力フォルダの実体です。権限確認のために本番監視先へ試験ファイルを作らないでください。

### B-3. 出力を伴わない自己診断

PowerShellで次を実行します。

```powershell
& 'C:\Apps\CHKanban\run_ch_kanban.bat' --self-test
```

使用conda、実際の `sys.executable`、Pythonバージョン、必須ライブラリ、設定・履歴・ローカル出力・stagingの解決先を確認します。`[OK] Startup diagnostics passed` が表示されれば診断成功です。**GUI起動、本番入力の読込、SPO出力、設定の作成・移行は行いません。** 起動ログのみ本人領域へ保存します。

### B-4. 初回起動で入力先・出力先を選ぶ

1. 共通の `run_ch_kanban.bat` をダブルクリックします。ショートカットを作る場合も同じbatを指します。ショートカットの「作業フォルダー」に依存せず、batのある場所を基準に起動します。
2. 初回のフォルダ選択で、B-2で確認した**本人の入力フォルダ**を選択します。
3. 続いて、**本人の出力フォルダ**を選択します。正常に保存されると本人の設定JSONへ記録されます。
4. 入車時間マスタが未配置の場合は、GUIに表示された配置先を確認します。通常は選択した入力先（`base_dir`）直下です。別マスタへ勝手に切り替えることはありません。
5. 読込・表示を確認します。実際のSPO出力を伴う試運転は管理担当者と調整してください。

**河崎本人もこの版での通常起動初回は選び直しが必要です。** repo内config、アプリ隣の旧設定、旧終了時刻履歴は自動移行しません。他ユーザーのパスも引き継ぎません。旧データの移動・削除・自動コピーは行いません。

キャンセルして終了を選んだ場合、代わりの場所は採用しません。それまでに正常に保存した入力先等は保持されます。次回は未設定の項目を選択します。保存先が不存在・不正なら案内して再選択し、書込失敗は成功扱いにしません。

### 保存先一覧

基準は `%LOCALAPPDATA%\CHKanban`。`LOCALAPPDATA` が未設定・空なら本人ホームの `AppData\Local\CHKanban` を使用します。必要な親フォルダは保存時に作成します。

| 対象 | 保存先 |
|---|---|
| 設定 | `ch_kanban_settings.json` |
| 前回工程終了時刻履歴 | `lane_end_times_history.json` |
| ローカル履歴Excel・未ヒットCSV・監査CSV | `output/` |
| アプリログ・bat起動ログ | `output/logs/`（起動ログは `startup_*.log`） |
| 既定アーカイブ | `output/_export_archive/` |
| SPO一時作成 | `output/_staging/` |
| SPO本体 | 本人が選択した `export_dir`。形式・ファイル名・作成後の移動方式は従来どおり |
| 入車時間マスタ | 通常は `base_dir/入車時間マスタ.xlsx` |
| マスタ保存失敗時の救済コピー | 従来どおり本人の一時フォルダ（表示された場所を確認） |

- `archive_dir` を明示した場合はその設定を優先します。共通アプリ配置先を指定しないでください。
- `master_path` を明示する既存仕様（ファイルまたはフォルダ）は維持します。本人の同期先の絶対パスを設定してください。指定先が未配置・利用不可でも別マスタへ自動変更しません。
- 設定JSONは同じフォルダの固有名一時ファイルから置換し、既存キーを保持します。不正JSON・非辞書JSONは警告を記録し未設定として扱い、読込権限エラーは空設定として上書きしません。
- アプリ配置先へ設定・ログ・履歴・stagingを書きません。bat起動ではPythonのバイトコード生成も無効にしています。

## C. 毎日の起動と担当交代

1. 本人のWindowsアカウントでサインインし、OneDriveの同期状態を確認します。
2. 同じ共通batを起動します。保存済みの入力先・出力先が有効なら、2回目以降の選び直しは不要です。
3. **終了時刻履歴はWindowsユーザー別です。担当交代時に他ユーザーの終了時刻は自動共有されません。** 必要に応じて前担当者から終了時刻を引き継ぎ、既存画面で指定・確認してください。
4. 共有マスタの同時編集は避けます。Excelや他担当者のアプリで編集中なら、保存前に調整してください。
5. **ローカル保存完了とOneDriveからSPOへの同期完了は別**です。SPO側での反映が必要な場面では同期完了も確認します。
6. Windowsユーザーを切り替える前にアプリを終了します。終了時刻の保存失敗が表示された場合は必要な時刻を控え、次回に確認します。

## D. アプリ更新

1. 更新担当者は全利用者へ連絡し、**全員がアプリと共有マスタの編集を終了**したことを確認します。
2. 現行版を戻せるよう、共通ソースの版を記録・保管します。実データや個人設定を更新資材へ混ぜません。
3. 承認済みの同一バージョンのソース・bat・`scripts/`・手順書を共通配置先へ更新します。起動中にファイルを置換しないでください。
4. 各ユーザーの `%LOCALAPPDATA%\CHKanban` とOneDriveフォルダは置換・削除しません。今回の更新では旧設定・旧履歴を自動コピーしません。
5. 代表ユーザーで自己診断、続いて利用する各Windowsユーザーで初回または再起動の確認を行います。ライブラリ変更が必要な将来版では、承認済み手順で各自の環境も更新します。
6. 別ユーザーの実働PC確認が済むまでは、編集用PC・自動テストだけで全員の利用確認済みとは扱いません。

## 困ったとき

| 表示・症状 | 確認すること |
|---|---|
| `CH_KANBAN_ENV_PREFIX` 未設定・不正 | 本人のユーザー環境変数にDIG_newの絶対パスを指定したか。登録後に起動元を開き直したか |
| condaが見つからない・拒否される | 本人用または承認済み全ユーザー用condaか。古い `CONDA_EXE` が他人のフォルダを指していないか |
| Python・ライブラリ診断失敗 | 本人のDIG_newがPython 3.11で必要ライブラリを持つか。baseやシステムPythonで代用しない |
| PowerShellの実行が禁止される | 組織の管理者へ相談する。ポリシー回避・セキュリティ製品停止はしない |
| 保存・起動ログ作成に失敗 | 本人領域の空き容量と権限を確認する。共通配置先への保存へ切り替えない |
| 入力先・出力先が選び直しになる | 本人のOneDrive同期先が存在するか。設定が不正JSON・非辞書JSONになっていないか |
| マスタ未配置 | GUIが示すbase_dirまたは明示master_pathへ正しいマスタを同期・配置する。アプリ隣へ置いて代用しない |

操作の詳細は [利用マニュアル.md](利用マニュアル.md)、仕分け・割り振りのルールは [仕分け・割り振りルール.md](仕分け・割り振りルール.md) を参照してください。exe関連の過去ガイドは今回のbat共通配置手順では使用しません。
